How Stats works

Where every number comes from, what Stats changes on your computer (very little), every setting and shortcut, and what the installers do. Written for people who like to know what runs on their machine.

Overview Windows Linux Settings Shortcuts Installers Privacy Troubleshooting

Overview

Stats is two native programs that behave the same way:

  • Windows: one small stats.exe written in Rust against the Win32 API. No web view, no runtime, no service, no administrator rights.
  • Linux: a GNOME Shell extension (JavaScript, GNOME 46 to 50). GNOME only runs extensions written in JavaScript, so it is its own program.

They share behaviour, not code: the same setting names, the same warning levels idea and the same layout. One file in the source, shared/defaults.ini, lists every shared setting and its default, and the build fails if either app drifts from it. The decisions that need no operating system (when to warn, which program to blame, what counts as a build folder, how the readings fit, how the activity wave moves) live in a platform-neutral Rust library, core/, with unit tests. The macOS version will reuse it.

The short version: Stats only reads counters the operating system already keeps. It changes something only when you click a button that says so (Close, Clean, Delete, Prune), and it asks first.

Windows, in depth

What you see

  • The activity line. A hairline on the top edge (centred) or on the left or right side (vertical). At rest it lets every click through to whatever is underneath, so a browser's tabs keep working. Rest the pointer on it for about a third of a second, or press Ctrl+Alt+R, and it wakes into a small "island" with voice-meter bars; click it for the readings.
  • The readings. A frosted panel with every reading: one row under a top line, or one reading per row beside a side line. It fades away 4 seconds after the pointer leaves unless pinned.
  • The dashboard. A frosted window in the middle of the screen with two tabs: Overview (live tiles, details, fixes) and Settings.
  • The tray icon. Its bar fills with committed memory; click it for the dashboard, right-click for a short menu.

Who is using the memory

Only while there is a warning or the dashboard is open, a background thread takes a ToolHelp snapshot (CreateToolhelp32Snapshot) and reads each process's private bytes (the memory that counts against the commit limit), then groups processes by program: "Chrome ×36 = 5 GB" rather than 36 rows. CPU per program needs two samples, taken 0.8 s apart.

When commit, RAM or CPU stays above its warning level for three polls in a row, Stats names the biggest program in a notification with one next step. Repeat warnings about the same thing wait at least notify-quiet-minutes; a jump from warning to critical is always reported.

What happens when you click a fix

  • Close posts WM_CLOSE to the program's windows, exactly like clicking its ✕, so it can ask you to save. Only if it is still running afterwards does Stats offer Force end (TerminateProcess).
  • Stats never offers to close parts of Windows: System, Registry, smss, csrss, wininit, winlogon, services, lsass, svchost, dwm, explorer, Defender and the like are on a fixed protected list.
  • Shut down (WSL/Docker) runs wsl --shutdown. Prune runs docker system prune -f, which keeps volumes. Compact shrinks Docker's virtual disk and first checks Docker Desktop is closed.
  • Clean (Temp) deletes files in your Temp folder, skipping files in use. Clean (caches) runs npm cache clean, go clean -cache, pip cache purge and pnpm store prune for the tools you have.
  • Nothing is closed or deleted without a Yes in a confirmation box first.

Build folders

Stats scans the folders in scan-roots at background priority (THREAD_MODE_BACKGROUND_BEGIN, which also lowers disk priority). A folder only counts as build output when the file that proves it sits next to it:

  • target needs Cargo.toml
  • node_modules, .next need package.json
  • build, .dart_tool need pubspec.yaml
  • .gradle needs a Gradle build file

A folder that just happens to be called build is never touched. The check is repeated right before deleting, deletion stays inside your scan folders, and links and junctions are never followed.

How it draws, and what it costs

  • The activity line is a per-pixel-alpha layered window. Stats computes its anti-aliased shapes itself into a 32-bit bitmap and hands it to UpdateLayeredWindow. It redraws 20 times a second while the wave moves, 4 times a second when nothing moves, and not at all while hidden.
  • At rest the line has WS_EX_TRANSPARENT, so clicks pass through. A cheap GetCursorPos check each frame notices when the pointer rests on it and removes that style to wake it.
  • The readings and the dashboard use the system acrylic blur (the accent policy behind SetWindowCompositionAttribute, Windows 10 1803 and later). Background pixels are painted partly transparent so the blur shows; text stays solid. Without it they are drawn solid.
  • The line hides while a game or video is full screen (SHQueryUserNotificationState) and stops drawing while the screen is locked (WTSRegisterSessionNotification).
  • Measured on a 12-thread laptop: about 0.1% of the whole machine while the wave is moving, around 18 MB working set.

Linux, in depth

What you see

The readings live in the top bar, left or right of the clock, with download and upload speeds next to it. Click them (or press Ctrl+Alt+S) for the dashboard. It is laid out like the Windows one: a status chip, six live tiles with graphs, folding cards, the programs using memory, and quick controls. It is frosted with the shell's own background blur (Shell.BlurEffect), so the windows behind it show through.

Programs, Close and Force end

Only while the dashboard is open, Stats reads /proc/<pid>/stat and /proc/<pid>/status every 3 seconds, in small asynchronous batches, keeps your own processes (matching Uid) and groups them by name. Close shows a GNOME confirmation, then runs kill -TERM on every process of that program: the same request to quit a program gets when you log out, so save your work first. If any is still running 5 seconds later, a notification says so and the button becomes Force end, which after a second confirmation runs kill -KILL. The shell itself and parts of the desktop (gsd-*, Xwayland, PipeWire, systemd, D-Bus and the like) never get a button.

Where the numbers come from

ReadingSource
CPU/proc/stat: busy share between polls (idle + iowait against total). Frequency from scaling_cur_freq when cpufreq exists.
Memory/proc/meminfo: MemTotal − MemAvailable.
StorageSpace per mount point; speed from /proc/diskstats (512-byte sectors), skipping loop, ram and device-mapper devices and partitions whose disk is already counted.
GPUVendor from /sys/class/drm/card*/device/vendor. A card whose runtime PM status is suspended shows idle/off and is never queried, so a sleeping discrete GPU is not woken. NVIDIA: one long-lived nvidia-smi -l 1. AMD: sysfs. Intel: GT frequency from sysfs, engine use while intel_gpu_top runs.
Temperaturehwmon (Intel coretemp, AMD k10temp Tctl/Tdie, NVMe, amdgpu) and the x86_pkg_temp thermal zone.
Network/proc/net/dev, skipping loopback.
Refresh rateMutter GetCurrentState on D-Bus (org.gnome.Mutter.DisplayConfig), updated on MonitorsChanged. This is the nominal mode rate; variable-refresh panels do not report an instantaneous rate, so none is invented.

Settings are GSettings keys (schema org.gnome.shell.extensions.stats, stored in dconf). Polling pauses while the screen is locked or the session is idle, and folded dashboard sections are not refreshed at all. Optional tools that are not installed simply show n/a.

What the installers do

Windows: install.ps1

  1. Checks for 64-bit Windows 10 or 11. No administrator rights are used.
  2. Downloads stats.exe, uninstall.ps1 and SHA256SUMS from the latest GitHub release (or the one in STATS_VERSION), retrying a dropped connection.
  3. Verifies both files against SHA256SUMS. On a mismatch it stops and changes nothing.
  4. Stops a running Stats (found by its window, so a copy started from Downloads is stopped too), copies the files to %LOCALAPPDATA%\Programs\Stats, adds the Run value, a Start Menu shortcut and the Settings › Apps entry, and starts Stats.

Linux: install.sh

  1. Refuses to run as root; checks GNOME Shell 46–50 and that gnome-extensions, glib-compile-schemas, gsettings and curl exist, naming the package to install if one is missing.
  2. Downloads the extension zip and SHA256SUMS and verifies the zip.
  3. Unpacks into a staging folder beside the extensions folder, compiles the schema, then swaps it into ~/.local/share/gnome-shell/extensions/stats@local in one step, so a failed download never leaves half an install.
  4. Enables the extension (recording it in enabled-extensions when the running Shell has not seen it yet).

Running either installer again upgrades in place and keeps your settings. Uninstall with … | bash -s -- --uninstall or irm …/uninstall.ps1 | iex (or Settings › Apps on Windows).

Privacy and permissions

  • No network use. Stats reads local counters only. The installers contact GitHub to download a release; the website asks GitHub for the latest version number. Nothing else.
  • No telemetry, no accounts, no ads.
  • No administrator rights. Everything Stats reads is available to a normal user, and everything it writes is in your own profile.
  • Your files are safe by default. The only deletions are the ones you confirm (build folders, Temp, caches, Docker), with the safety rules above.

Troubleshooting

The line covers part of my browser tabs.

At rest it only draws on the outer few pixels and lets clicks through, so tabs under it still work. If you prefer it out of the way, choose Left side or Right side in Settings, or turn the line off and use Ctrl+Alt+R.

A shortcut says "in use by another app".

Another program registered that combination first. Press Change next to it in Settings and choose another, or turn it off with Clear.

A new version will not start.

Only one Stats runs at a time. If you started a stats.exe from another folder (say Downloads), quit it from its tray menu; running the installer again also stops it.

The readings and dashboard are not frosted.

The blur needs Windows 10 version 1803 or later with transparency effects on (Settings › Personalization › Colors). Without it they are drawn solid; everything else works the same.

Linux: the indicator does not appear after installing.

GNOME on Wayland loads new extensions only at login: log out and back in once. On X11 press Alt+F2, type r and press Enter.

Where is the log?

Windows: %APPDATA%\Stats\stats.log (Settings › System › Open log). It records warnings, settings problems and, if Stats ever crashes, where. Linux: journalctl -f -o cat /usr/bin/gnome-shell.
